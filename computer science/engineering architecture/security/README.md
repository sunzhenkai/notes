# 认证与授权

认证与授权是身份与访问管理（Identity and Access Management，IAM）的两个核心环节：认证确认访问者是谁，授权判断该访问者能做什么。两者必须分开设计，但在一次请求中连续完成。

## 核心概念

| 概念 | 英文 | 回答的问题 | 典型产物 |
|------|------|------------|----------|
| 身份识别 | Identification | 访问者声称自己是谁？ | 用户名、主体 ID、服务账号 |
| 认证 | Authentication（AuthN） | 如何证明这个身份？ | 会话、认证上下文、令牌 |
| 授权 | Authorization（AuthZ） | 该主体能对目标执行什么操作？ | 允许或拒绝的策略决策 |
| 审计 | Auditing / Accounting | 谁在何时做了什么？ | 安全日志、审计事件 |

典型处理链路如下：

```text
声明身份 → 验证凭据 → 建立会话或签发令牌 → 对每次资源访问做授权 → 记录审计事件
```

认证成功不代表可以访问任意资源；授权也不能只在登录时执行。服务必须在可信边界内解析身份，并在每次敏感操作前根据主体、动作、资源和上下文重新做授权决策。

## 基本原则

1. **默认拒绝**：没有明确允许的请求一律拒绝。
2. **最小权限**：只授予完成当前任务所需的最小权限，并限制作用域和有效期。
3. **服务端强制执行**：前端隐藏按钮只能改善体验，不能代替服务端校验。
4. **纵深防御**：认证、授权、数据隔离、审计和告警共同构成防线。
5. **凭据最小暴露**：使用 TLS，缩短令牌寿命，安全存储密钥并支持轮换和撤销。
6. **关键操作可追溯**：记录主体、动作、资源、结果、策略版本和请求关联信息，避免记录密码、完整令牌等秘密。
